# 文章发布后端修复

此包仅包含 Go 后端程序和源码；前端文件在 `docs.wjdun.cn/frontend-article-publish.zip` 中，需分别部署。

## 部署

1. 备份并停止现有 Go 服务。
2. 用 `go-admin-linux-amd64` 替换原 Linux amd64 服务程序，赋予执行权限。保留服务器上的 `configs` 和数据库。
3. 设置一个持久化、可写的图片目录，例如 `ARTICLE_UPLOAD_DIR=/var/lib/go-admin/uploads/articles`；未设置时使用服务工作目录下的 `uploads/articles`。
4. 重启服务，确认前端域名的反向代理将 `/api/upload` 与 `/api/uploads/articles/*` 原样转发到该服务。代理的请求体大小限制应按实际图片大小配置。
5. 再部署独立的前端包，并清理旧 JS 缓存。

部署后用 `curl -i -X POST https://docs.wjdun.cn/api/upload` 检查路由。未登录时应返回 401；若仍返回 404，检查运行中的后端程序版本，以及前端域名到后端的 `/api/` 转发规则。登录后上传图片应返回图片地址，打开该地址应能读到图片。

### 上传仍返回 404 时

先在后端服务器执行 `curl -i -X POST http://127.0.0.1:8082/api/upload`。这里的 `8082` 来自 `configs/config.yaml`，若线上修改过监听地址，以实际值为准。

- 本机也是 404：当前监听端口的进程仍是旧程序。确认替换了正在使用的程序文件并重启服务；用 `ss -ltnp | grep ':8082'` 查监听进程，用 `readlink -f /proc/<PID>/exe` 查实际运行路径。仅复制新程序到磁盘不会更新已运行的进程。
- 本机是 401，公网仍是 404：检查前端站点的反向代理。Nginx 需要将 `/api/` 原样转发到后端，例如 `location /api/ { proxy_pass http://127.0.0.1:8082; }`；修改后执行 `nginx -t` 并重载配置。若前后端在不同服务器，将 `127.0.0.1` 改为后端可访问的地址。

以上无登录凭据的检查返回 401 即说明上传路由已生效。不要使用 GET 请求判断 POST 路由。

后端使用数据库中的当前角色菜单权限校验文章接口，避免权限变更后仍使用旧缓存；新增文章图片上传与读取接口。普通用户仍需拥有文章创建或编辑权限。

`source/` 是修复后的 Go 源码，不含服务器配置文件和依赖缓存。
